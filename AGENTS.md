# AGENTS.md

Общие инструкции проекта для Codex и Claude Code. `CLAUDE.md` подключает этот файл.

## Общение и границы задачи

- Отвечай по-русски, включая сообщения субагентов. Описания задач и PR пиши по-русски; имена инструментов, идентификаторы и команды сохраняй в исходном виде.
- Пиши кратко: что меняется, зачем и как проверено.
- Изменяй только то, что относится к задаче. О найденных сторонних проблемах сообщай отдельно.
- Сохраняй изменения пользователя. Не читай `.env` и `.env.*`; необходимые несекретные значения запрашивай отдельно. Не выполняй `rm -rf`.

## Навыки и документация

Используй навыки Matt Pocock для планирования, реализации, диагностики и ревью. Правила проекта определяют объём тестов и обязательные проверки, если они отличаются от рекомендаций навыка.

- Перед исследованием кода прочитай [правила доменной документации](docs/agents/domain.md): термины находятся в корневом `GLOSSARY.md`, решения — в `docs/adr/`.
- Перед чтением, созданием или обновлением задач прочитай [правила трекера](docs/agents/issue-tracker.md). Работа ведётся в Linear: команда **Fatbook**, пространство **Sketchyy**.
- Перед триажем прочитай [соответствие меток](docs/agents/triage-labels.md).
- При планировании этапов поставки читай и обновляй через Linear MCP [Fatbook — Roadmap](https://linear.app/sketchyy/document/fatbook-roadmap-3acdfae71c0b).
- Перед изменением мобильного кода прочитай [документацию Expo v56](https://docs.expo.dev/versions/v56.0.0/).

## Работа с задачами

Каждая фича и исправление связаны с задачей Linear. Указывай её идентификатор в коммитах: `feat(FAT-29): ...`, `fix(FAT-27): ...`.

Обновляй статус по ходу работы:

- **In Progress** — при начале реализации и при исправлении замечаний к PR.
- **In Review** — когда PR готов к просмотру владельцем.
- **Done** — после слияния PR в `main`, выполнения критериев приёмки и обязательных проверок.

Перед новой задачей и при запросе статуса сверяй Linear с фактически завершённой работой.

## Git и PR

1. Проверь ветку и состояние рабочего дерева. Работай в основной папке проекта: для новой задачи создай ветку `codex/FAT-<id>-<slug>` от актуального `origin/main`, продолжая задачу — используй её существующую ветку. Отдельный worktree создавай только по явному запросу владельца. Сохраняй незакоммиченные изменения пользователя; перенос его изменений или коммитов требует явного указания.
2. Работай и делай коммиты в ветке задачи. Указание навыка «commit to the current branch» относится к этой ветке. Прямые коммиты в `main` запрещены.
3. Выполни обязательные проверки и ревью через `code-review`, исправь найденные проблемы, затем закоммить изменения. Один PR содержит одно самостоятельное изменение, которое можно просмотреть и принять отдельно.
4. Открой PR в `main`. Описание оформляй через навык `pr`; дополнительно укажи ссылку на задачу Linear и 2–3 ключевых файла в порядке чтения с кратким пояснением их роли. Для меньшего изменения достаточно меньшего числа файлов.
5. Передай владельцу ссылку на PR. Слияние и включение auto-merge требуют его явного разрешения; разрешение реализовать задачу, создать коммит или открыть PR этого не заменяет. Перед разрешённым слиянием проверь актуальные результаты CI и ревью.

## Код

- Предпочитай простые, читаемые решения. Добавляй абстракции и зависимости при конкретной необходимости.
- Держи код рядом с местом использования; выноси его в общее место при появлении нескольких потребителей.
- Сохраняй типобезопасность TypeScript без `any`. Комментируй причины решений и неочевидную логику.
- В веб-интерфейсе соблюдай принятую структуру компонентов shadcn/ui. Чтения выполняются через сервисы `packages/api-client` и TanStack Query; записи дневника — через мутации с оптимистичными обновлениями, записи блюд — через существующие React actions.
- `packages/api-client/src/supabase.types.ts` обновляй только генерацией. После изменения схемы запускай из корня `npm run typegen` или `npm run typegen:local`.

## Тесты и проверки

Пиши тесты для переиспользуемой логики, утилит и библиотечных функций. Тесты UI-компонентов добавляй по явному запросу.

Перед каждым коммитом выполни из корня:

```bash
npx turbo lint typecheck test --filter=web
npx turbo typecheck --filter=@fatbook/mobile --filter=@fatbook/api-client --filter=@fatbook/shared
```

Исправь ошибки до коммита; не используй `--no-verify`. Если команда выполнила `0 tasks`, укажи, что соответствующая проверка не состоялась.

E2E-тесты работают с реальным Supabase и выделенным тестовым пользователем. Для них требуется настроенный `.env.test`; файл не читай. Данные между запусками очищаются командой `npm run test:e2e:cleanup` из `apps/web`.
